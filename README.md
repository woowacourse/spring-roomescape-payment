# 방탈출 결제, 배포

## 1단계

- [x] 결제의 amount와 orderId를 임시저장하는 API를 구현한다
- [x] 예약 시 결제 승인 단계를 추가한다
    - [x] orderId를 기준으로 임시저장된 amount와 예약 생성 요청의 amount를 비교한다
        - [x] 일치한다면 토스 결제 승인 API를 호출한다
        - [x] 일치하지 않는다면 예외를 발생시킨다
    - [x] 결제 승인이 성공했다면 예약을 생성한다
    - [x] 예약 실패 시 클라이언트가 실패 사유를 알 수 있도록 예외를 핸들링한다

## 2단계

- [x] 사용자가 직접 예약을 생성할 때 예약은 결제를 통해 승인된다
- [x] 관리자가 사용자의 예약을 생성해줄 때 예약은 관리자 승인을 통해 승인된다 (별도의 결제가 필요하지 않다)
- [x] 기존 예약이 삭제되어 예약 대기가 예약으로 자동으로 승격될 때, 현장 결제를 통해 승인된다 (별도의 결제가 필요하지 않다)
- [x] 내 예약 조회에서 예약 승인 방식을 조회할 수 있다
    - [x] 승인 방식이 결제인 경우 결제 키와 결제 금액을 조회할 수 있다
    - [x] 승인 방식이 관리자 승인일 경우, 예약을 승인한 관리자의 이름을 조회할 수 있다
    - [x] 승인 방식이 현장 결제일 경우, 결제(예정) 금액을 조회할 수 있다

## 3,4 단계

- [x] 서비스를 AWS EC2를 통해 배포한다
- [x] API 문서화 작업을 진행한다
- [x] 로그 레벨을 구분하여 로그를 기록한다
- [x] Database ERD를 작성한다
