## 고민한 점
1. Payment가 Reservation을 가질지 Reservation이 Payment를 가질지
    - Reservation이 Payment를 가지게 된다면 Reservation에 너무 많은 책임이 있는 것 같다
    - 구조상 Reservation이 먼저 예약이 되고 결제가 되어야 한다고 생각한다.
      - 만약 Payment가 먼저 결제가 되고 Reservation 예약에서 에러가 터진다면 결제취소를 해주는 것보다. 우리 서비스인 예약을 취소해주는 것이
      더 간단한다고 생각함 (외부 API인 결제와 우리 서비스인 Reservation을 하나의 트랜잭션에서 관리하는 것이 불가능하니)
2. 그렇다면 Payment가 Reservation을 객체로 가져서 연관관계 매핑을 맺어야 하나??
    - 결제를 통해서 Reservation을 보여주는 결제 내역 확인이라는 요구사항이 있다면 Reservation을 가지는 것이 더 좋아보이는데,
    지금 구조에서는 예약을 통해서 결제 내역까지 보여주고 실질적으로 필요한 것은 Reservation의 Id값만이지 않나??
